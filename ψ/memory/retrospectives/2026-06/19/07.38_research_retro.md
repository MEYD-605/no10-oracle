## What Could Improve
*   Initially used the invalid `--limit` flag in `gh api`, which caused command failures.
*   Using `-F` in `gh api` for query parameters mistakenly triggered a POST repository creation request (422 error) because `gh` defaults to POST when form fields are present.

## Blockers & Resolutions
*   *Blocker*: Public organizations list for `nazt` only returned `cmmakerclub`.
*   *Resolution*: Inspected the authenticated profile's private memberships to access the full organization list.

## Honest Feedback (100+ words, 3 friction points)
*   **gh api flag constraints**: We ran into issues trying to use `--limit` inside the `gh api` parser. This required refactoring to use native `--paginate` parameter.
*   **Automatic mutation triggers**: When calling `gh api` with `-F`, it automatically converted GET requests to POST requests, causing 422 errors when attempting to query repository structures. We had to use query parameters in the URL path.
*   **Private membership masking**: GitHub's API hides membership in organizations if the member has not explicitly clicked "Public" on their profile, creating discovery barriers that require active sessions to bypass.

## Lessons Learned
*   **Leverage Authenticated Contexts**: Public organization endpoints on GitHub mask private organization memberships. When mapping developer organizations, verify memberships via the authenticated user profile `user/orgs` rather than just `/users/{username}/orgs`.
*   **Sanitize gh api parameters**: Do not use form field parameters (`-F`) for query constraints in `gh api` GET calls, as GitHub will interpret it as a POST payload and fail. Use `--paginate` for full list extraction.
